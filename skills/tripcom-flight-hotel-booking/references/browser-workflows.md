# Browser Workflows

Search, compare, log in through an existing profile integration, use saved sessions and an available payment descriptor, and prepare checkout. Prefer the configured browser route; if it fails, use another attended browser while preserving the same action checkpoint.

Stop once at final booking/payment, cancellation, material profile/payment change, nonrefundable/unclear terms, outbound messages, calls, or human verification that still requires a response after configured browser lanes are tried.

Use a final confirmation summary for final actions. After confirmation, compare the live page with the packet before clicking the final action; in a Browserbase session the user clicks it in the live view. If price, dates, traveler, refund terms, payment descriptor, merchant, or final button changed after confirmation, ask again.

# VA scorecard

Run `python -m evals.scorecard --version V --commit SHA --lab DIR --as-of YYYY-MM-DD --out DIR`, optionally repeating `--lab` and `--live FILE` (one export per owner; duplicate baseline or day30 owner keys are rejected). The JSON stores lab directory basenames only and names runs as `<lab basename>/<run folder>` in test run IDs, exclusions and fact errors; local paths are omitted. The Markdown omits paths and URLs. Only completed runs pinned to the full PA commit count (PA's `plugin-refs.json` entry is found by name, then by source, then first position; hand-built lab homes list heartbeat2 first), and partial checks never establish a full-area pass. Live task dates are ISO dates: the observed window runs from the first start to the earlier of the last due date and `--as-of` (the export has no completion timestamp; tasks starting after `--as-of` are ignored), counting both endpoint days, and pending tasks count as failures only after their due date. Missing owner baseline/day-30 records leave day-30 unproven; first-pass task types count distinctly. The command reports failures with exit 0 and rejects bad input with exit 2. Synthetic tests prove scoring rules, not real lab quality, publication, runtime activation or customer parity. Related issue: #48.

Catalogue tests may declare `covers`, a list of zero-based indices into their area's `duties`; it defaults to `[]` for every existing test. Only tests in state `pass` cover a duty. Each JSON area includes `uncovered_duties`, and the Markdown's "Unexercised duties" section lists those duties for every area, including areas with passing full tests. The headline always includes both passing and failing partial-check counts (`· N partial checks failing`, even at zero), and never a parity percentage.
